# Почасовые услуги · TL Mobile

Кликабельный прототип по [мобильным макетам в Figma](https://www.figma.com/design/iC8R8NAxEZILEpw0ZjUyUp/?node-id=500-55624). Работает локально и на GitHub Pages, без сервера приложения и внешних зависимостей.

## Публикация на GitHub Pages

Эта папка — самостоятельный проект. Поместите **её содержимое в корень отдельного репозитория**, включая скрытую папку `.github`. Не загружайте весь родительский каталог «Реактор — Библиотека компонентов». Структура в репозитории:

```text
.github/workflows/pages.yml
.gitignore
.nojekyll
index.html
styles.css
app.js
model.js
build.mjs
server.mjs
package.json
scripts/check-pages.mjs
tests/model.test.mjs
README.md
```

1. Создайте репозиторий на GitHub и загрузите в него содержимое проекта. Не загружайте ZIP как единственный файл — сначала распакуйте архив.
2. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. В **Actions** выберите **Deploy prototype to GitHub Pages → Run workflow**, выбрав основную ветку репозитория. Дальнейшие push в основную ветку будут публиковаться автоматически; изменения в других ветках и pull request проходят проверки без публикации.
4. После успешного выполнения ссылка появится в **Settings → Pages** и в environment `github-pages`. Обычный адрес проекта: `https://USERNAME.github.io/REPOSITORY/`.

Workflow использует Node.js 24, проверяет синтаксис, запускает тесты, собирает `dist/` и публикует только файлы сайта. Имена пользователя и репозитория в коде менять не нужно: все ресурсы подключены относительными путями. Секреты и токены вручную добавлять не требуется.

Настройка источника публикации описана в [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). Workflow использует [официальные Pages actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### Подготовка файлов сайта вручную

```bash
node --test tests/model.test.mjs
node build.mjs
node scripts/check-pages.mjs
```

В `dist/` будут только `index.html`, `styles.css`, `app.js`, `model.js` и `.nojekyll`. Эта папка подходит и для других статических хостингов. При публикации через workflow не нужно коммитить `dist/`: она создаётся автоматически.

## Запуск

Нужен Node.js 20+. Установка пакетов и сборка не требуются.

```bash
node server.mjs
```

Откройте http://127.0.0.1:4173. Для другого порта: `PORT=4174 node server.mjs`.

## Основной кейс

1. «Добавить ещё услугу» → «Почасовая услуга» → «Добавить».
2. Группа «Бани», услуга «Аренда парной».
3. Дата 26 марта 2026, начало 11:00.
4. Выберите сотрудника и место. Окончание 11:45, стоимость 1 500 RUB.
5. Укажите количество гостей, счёт и при необходимости комментарий.
6. «Добавить услугу» → новая услуга в списке → «Применить».

Время 10:00 демонстрирует автоматический выбор единственного свободного сотрудника, места или велосипеда. В 11:00 изначально доступно несколько ресурсов; в 12:00 всё занято. Изменение даты сбрасывает время и ресурсы; изменение начала сбрасывает ресурсы и продление. Попытка добавления неполной формы показывает ошибки. Добавленную услугу можно открыть, изменить и удалить. Отмена формы не меняет список.

## Даты, время и доступность ресурсов

- Услуга доступна только на даты проживания 26–28 марта 2026 включительно. Время выезда 12:00 не ограничивает услуги 28 марта: например, можно добавить парную на 17:00–17:45.
- Даты вне проживания и полностью занятый день 27 марта отключены в календаре. Занятые интервалы отключены в выборе начала. В демонстрации услуги работают с 10:00 до 18:00.
- Доступность проверяется на весь интервал, включая продление. При продлении ресурсы пересчитываются; недоступные выбранные ресурсы сбрасываются или заменяются единственным свободным вариантом.
- Выбор сотрудника, места или инвентаря открывается только при наличии более одного свободного варианта соответствующего типа. Единственный свободный вариант назначается автоматически и отображается без возможности выбора.
- Добавленные услуги занимают выбранные ресурсы сразу, до нажатия «Применить». Повторное занятие тех же ресурсов на пересекающиеся интервалы запрещено. При редактировании услуга не конфликтует сама с собой; удаление освобождает ресурсы.
- Проверки повторяются при добавлении, сохранении изменений и применении к бронированию. Старые сохранённые демонстрационные услуги, нарушающие новые условия, не восстанавливаются.

На большом экране слева доступны демонстрационные кейсы с уже выбранными услугой, датой и временем. На телефоне все варианты доступны через обычный выбор группы и услуги.

## Допущения демонстрационных данных

- Детальная ветка парной: 1 500 RUB / 45 минут; продление +500 RUB / 15 минут. Цена умножается на число гостей, доплата за продление прибавляется к результату за использование.
- Бассейн: взрослый — 1 500 RUB, ребёнок 2–10 лет — 750 RUB. Категория 11–15 лет не включена: в исходных макетах не определена её цена. Для «Плавание (1 час)» сохранена длительность 45 минут из макетов; название и длительность в исходнике расходятся.
- Инвентарь: 500 RUB за гостя. Выбор нескольких велосипедов сам по себе не меняет число гостей и стоимость.
- Беседка: 5 000 RUB за базовых 4 гостей, +500 RUB за дополнительного гостя. Неоднозначный лимит исходника трактуется как максимум 10 дополнительных гостей.
- Сервер бронирования не подключён: доступность ресурсов демонстрационная. Изменения списка сохраняются в localStorage только после «Применить». Кнопка «Начать заново» сбрасывает демонстрационные данные.
- Общие услуги и питание обозначены в выборе типа; интерактивно реализован запрошенный почасовой сценарий.
- Roboto используется при наличии в системе, иначе — Arial. Остальной интерфейс не требует внешних ресурсов.
